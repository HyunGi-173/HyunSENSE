> **Love, in the little things.** 사랑은 작은 것을 기억하는 것부터.

## 1. 로컬에서 실행

Python 3.11 이상을 설치합니다.

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS / Linux: source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

설정 없이 실행하면 **체험 모드**입니다. 변경 내용은 열려 있는 Streamlit 세션에만 존재하므로 실제 개인정보를 입력하지 말고 샘플 데이터를 사용하세요. 체험 중에도 암호화된 백업을 내보내고 복원할 수 있습니다.

## 2. 비밀번호·암호화 저장 설정 (실사용)

```bash
python setup_secrets.py
```

12자 이상 비밀번호를 입력하고 생성된 다음 두 줄을 **`.streamlit/secrets.toml`**에 보관하거나 Community Cloud 앱의 **Secrets**에 입력합니다.

```toml
ACCESS_PASSWORD_HASH = "<setup_secrets.py에서 생성한 해시>"
DATA_ENCRYPTION_KEY = "<setup_secrets.py에서 생성한 Fernet 키>"
```

두 항목을 모두 설정하면 비밀번호로 접근을 제한하며, 저장 전 JSON 내용이 Fernet 방식으로 암호화됩니다. 로컬에서 사용하면 `data/hyunsense.sqlite3` 파일에 기록됩니다. 이 파일과 Secrets는 `.gitignore`에 포함되어 있습니다. 비밀번호를 잃어버리거나 암호화 키가 변경되면 기록을 복구할 수 없습니다. 비밀번호 유출 시 즉시 교체하세요.

> 주의: 이 버전은 **단일 사용자 계정용**입니다. 다중 사용자 서비스·의료정보 플랫폼으로 운영하려면 전문적인 인증, 접근제어, 감사, 보안 점검과 법적 검토가 별도로 필요합니다. 로그인 실패 제한은 서버 프로세스 전체에 적용되지만 프로세스 재시작·다중 인스턴스에 걸쳐 유지되지 않습니다. 공개 인터넷에서 강한 공격 방어를 보장하지 않습니다.

## 3. Streamlit Community Cloud 배포

1. 새로운 GitHub 저장소(예: `HyunSENSE`)를 만들고 이 프로젝트 파일을 최상위에 올립니다. **실제 `secrets.toml` 및 데이터 파일은 업로드 금지**.
2. [Streamlit Community Cloud](https://share.streamlit.io)에서 **Create app → Deploy a public app from GitHub**를 선택합니다.
3. Repository는 `GitHub계정/HyunSENSE`, Branch는 `main`, **Main file path는 `app.py`**로 지정합니다.
4. Advanced settings → **Secrets**에 위 해시와 암호화 키를 입력합니다.
5. **영구 저장이 필요한 경우** 외부 PostgreSQL 연결 문자열을 추가해야 합니다.

```toml
DATABASE_URL = "postgresql://<사용자>:<암호>@<호스트>:5432/<데이터베이스>?sslmode=require"
```

DB 제공업체의 TLS 연결이 가능한 PostgreSQL URL 또는 pooler 연결 문자열을 사용하세요. 앱은 `hyunsense_data` 테이블을 자동 생성합니다. **Community Cloud 로컬 파일은 앱 재시작·재배포 때 사라질 수 있어 영구 저장 보장 안 됨**. PostgreSQL이 없다면 배포용 체험판으로만 사용하고 JSON 백업을 내려받으세요.

**설정 예시**: GitHub Pages에서 배포한 `HyunLunch`와 달리, 본 프로젝트는 Python 서버가 필요한 Streamlit 앱입니다. 기존 HyunLunch 저장소를 덮어쓸 필요가 없습니다.

## 4. 신규 기능: 마음 레이더 (채팅 분위기·배려 추천)

- **입력:** 두 사람이 분석에 동의한 카카오톡 대화 일부 또는 TXT 파일(2MB 이하). 직접 붙여넣기도 지원합니다.
- **참여자 선택:** 이름이 2개 이상 확인되면 분석 대상인 상대방의 메시지만 명시적으로 선택해야 합니다.
- **기본 분석:** 인터넷 AI 없이도 피로, 스트레스, 걱정, 서운함, 기쁨, 몸 상태 언급을 나타내는 **표현의 존재**를 확인합니다. **실제 감정의 판정·심리 진단이 아닙니다.** 부정문·타인 언급·질문을 보수적으로 제외하지만 반어·복잡한 문맥은 여전히 오해할 수 있습니다.
- **추천:** 상대가 직접 알려 준 배려 선호를 최우선으로 하고 취향 노트를 참고해 공감 메시지와 세 가지 실천 아이디어를 제안합니다. 배려 아이디어를 센스 미션에 담을 수 있습니다.
- **MBTI:** 선택 입력. 참고사항일 뿐 개인의 감정·행동을 예측하거나 고정관념으로 판단하지 않습니다.
- **비공개 처리:** 원본 메시지는 메모리에서 처리하고 DB·백업·로그에 저장하는 코드가 없습니다. 파일은 Streamlit 서버로 업로드되므로 **공개 서버가 아닌 신뢰할 수 있는 실행 환경에서 이용하고, 민감한 사적 대화는 사용하지 않거나 익명화해 주세요.**
- **데이터 제거:** '입력 대화 · 분석 결과 지우기' 버튼으로 입력 위젯을 초기화하고 요약 결과를 지웁니다. 이것이 서버나 클라우드 제공업체의 모든 메모리 복제·백업을 보장하는 것은 아닙니다.

### (선택) AI 심화 배려 코치

기본 분석은 API 키 없이 작동합니다. 추가 자연어 제안을 원하면 Streamlit Secrets에 아래 항목을 설정하세요.

```toml
OPENAI_API_KEY = "<본인 API 키>"
OPENAI_MODEL = "gpt-4.1-mini"
```

AI 버튼을 누르기 전에 **별도의 외부 전송 동의**가 필요합니다. 실제 대화 메시지·이름·연락처·메모 원문은 보내지 않으며, **분류한 주제의 건수, 선택한 MBTI·대화 선호, 취향 카테고리만 OpenAI API로 전송**합니다. `store=False`로 응답을 요청하지만 서비스 제공업체의 정책·기술적 처리에 따른 잔존 위험을 없앨 수는 없습니다. API는 별도 요금이 부과될 수 있습니다.

**중요:** 카카오 공식 API는 개인 채팅방의 과거 메시지를 자동으로 읽어오는 기능을 제공하지 않습니다. 본 앱은 상대방의 비공개 카톡 메시지를 몰래 수집하거나 카카오 계정에 접속하지 않습니다.

## 5. 월경 추정 로직

- 최근 월경 시작일과 설정한 주기 길이를 사용합니다.
- **유효한 간격이 2개 이상**이면 최근 6개 간격의 중앙값을 사용하고, 그렇지 않으면 사용자가 입력한 주기를 사용합니다.
- 다음 예상일을 **대략적인 참고 날짜**로 표시합니다. 기록 간격의 관찰된 변동성은 통계적 참고값일 뿐 **임상적으로 검증된 신뢰구간이나 확률이 아닙니다.**
- **다음 예상일이 지났는데 후속 기록이 없다면** 여러 주기를 임의로 건너뛰어 날짜를 만들지 않고 **기록 확인**으로 안내합니다. 마지막 기록이 120일보다 오래된 경우에도 예측하지 않습니다.
- **배란·가임기, 임신 가능성, 피임, 질환 진단, 성격·기분을 예측하지 않습니다.** 불규칙한 주기나 호르몬 요인 등이 있으면 실제 시점이 크게 달라질 수 있습니다.

## 6. 개인정보 보호

- 상대방의 월경 기록 **명시적 동의**를 받은 경우에만 기록하세요. 설정에서 동의를 철회하면 월경 기록과 배려 메모를 지웁니다.
- 암호화 저장은 기본적인 보호 조치이며 의료기관 수준의 규제 준수나 침해 방어를 보장하지 않습니다.
- 기본 백업은 비밀번호 기반 **암호화 파일(.hyunsense)**입니다. 이전 버전과 호환되는 평문 JSON도 별도 경고를 확인한 후 다운로드할 수 있으므로 외부 유출에 주의하세요.
- 앱은 이메일·문자·푸시를 직접 보내지 않습니다. 다만 **설정·데이터 → 캘린더**에서 `.ics`를 내려받으면 개인 캘린더로 기념일·미션 알림을 옮길 수 있습니다. 캘린더 제공업체에서 알림을 지원하고 활성화해야 실제 알림이 표시됩니다.
- 제3자 추적 SDK, 광고, 자동 위치 추적 기능을 포함하지 않습니다.

## v1.3 — 배포 전 최종 개선 (2026-11-13)

- **동의 철회 시 건강기록 차단:** 월경 기록, 관련 메모, 삭제 취소 및 미저장 초안에 남아 있는 건강기록 사본을 정리합니다. 월경 기록이 있는데 `consent=false`인 모순된 백업은 복원 단계에서 거부합니다. 월경 기록을 포함한 백업은 복원 시 **현재 공유 동의를 재확인**합니다.
- **월경 예정일의 보수적 계산:** 실제 월경 기록 없이 예상 시작일이 지나갔을 때 여러 주기를 건너뛰어 새로운 예측일을 생성하지 않습니다. 확인되지 않은 미래 시작일을 연달아 달력에 표시하는 기능도 중단합니다.
- **캘린더 내보내기:** 기념일과 미완료 미션을 `.ics` 파일로 내려받아 Google/Apple/Outlook 캘린더에 수동 등록할 수 있습니다. 기본값은 제목을 일반 문구로 마스킹하며, **월경 기록·채팅 원문·개인 메모는 포함하지 않습니다.** 기념일 알림은 7일·1일 전, 미션은 1일 전으로 설정합니다. 캘린더 동작은 가져오는 앱에 따라 다릅니다.
- **마음 레이더 새 분석 반영:** MBTI나 배려 선호를 변경하면 이전 분석을 무효화하고, 외부 AI 전송 동의를 해제하면 기존 AI 추천을 숨깁니다.
- **보안·사용성:** 암호화 모드에서 30분 비활동 뒤 다시 로그인하도록 세션을 잠그고, 수동 잠금 때 임시 입력값을 지웁니다. 삭제 취소는 저장 성공 후에만 표시합니다. 작은 화면에서 카드 설명의 말줄임을 줄였습니다.
- **검증:** 기존·신규 단위 및 회귀 테스트 **54개 통과**. 실제 Streamlit 서버/브라우저 및 운영 클라우드 연동 검수는 별도로 필요합니다.

## v1.2 — 정밀검수 반영 변경사항

- **동시 저장 충돌 감지:** SQLite/PostgreSQL에 `revision` 컬럼을 추가하고 비교 후 갱신합니다. 두 브라우저가 오래된 데이터를 덮어쓰려 하면 해당 저장을 중단하고 최신 상태를 불러옵니다. 이전 SQLite DB의 테이블에는 자동으로 `revision` 컬럼을 추가합니다.
- **미저장 데이터 보호:** 저장 충돌이나 DB 오류 시 마지막 편집본을 현재 세션 메모리에 유지하며 설정 화면에서 암호화 파일로 내보낼 수 있습니다. 기기 간 병합은 자동으로 수행하지 않으므로 사용자가 비교해서 재적용해야 합니다.
- **백업 안정성:** 중복 식별자, 허용되지 않는 데이트 상태·취향 분류·기념일 유형, 잘못된 월경 기간·날짜를 복원 전에 차단합니다. 구버전 평문 JSON은 여전히 가져올 수 있습니다.
- **마음 레이더:** 여러 줄 카카오 메시지를 이어서 읽고, 부정문·질문·제3자 언급을 확정적 감정 단서에서 보수적으로 제외합니다. 대화가 바뀌거나 동의가 해제되면 과거 분석과 AI 출력을 숨깁니다.
- **마법의 성:** 시작일 중복 및 비정상 종료일 입력 방지. 날짜 추정에 임의 ±범위를 임상적 신뢰구간처럼 표시하지 않습니다. 월경과 기분을 연결하지 않습니다.
- **일정·디자인:** 한국 시간(`Asia/Seoul`) 기준 D-DAY, 1900년까지 날짜 입력 가능, 화면 보조문구 대비 개선, 키보드 포커스 및 작은 화면 폰트 조정.
- **삭제 실행 취소:** 항목 삭제 후 사이드바에서 마지막 삭제 한 건을 되돌릴 수 있습니다. 데이터 전체 삭제는 실행 취소할 수 없습니다.

### 알아둘 제한

1. **개인용/비공개 용도**: 이 버전에는 여러 회원별 계정·권한 분리가 없습니다. 비밀번호 하나를 공유하는 단일 저장공간입니다. 공개 서비스용 인증·서버 간 로그인 시도 제한은 별도 구현이 필요합니다.
2. **정기 알림 미지원**: 기념일과 미션은 앱을 열었을 때만 보이며, 실제 푸시·문자·이메일은 보내지 않습니다.
3. **정확한 감정 판별 미지원**: 카톡 분석은 보수적인 한국어 표현 탐지이며, 마음을 추론하는 의학적·심리학적 진단이 아닙니다. MBTI로 감정을 예측하지 않습니다.
4. **DB 운영**: 동시저장 방지는 새 개정번호를 통해 동작합니다. DB 백업과 암호화 키는 운영자 책임입니다. `DATABASE_URL`을 사용하는 경우 TLS 및 DB 제공업체 보존/삭제 정책을 확인하세요.
5. **v1.2 당시 테스트 범위**: 당시 소스 문법 검사와 41개 순수 Python 테스트를 통과했으며, v1.3 현재는 **54개 테스트**를 통과했습니다. 이 작업 환경에서는 Streamlit 서버 패키지 설치가 불가능해 UI·모바일 실기기·실제 PostgreSQL/외부 AI 호출은 아직 통합 검증하지 못했습니다.

### 배포 시 먼저 확인할 항목

- Secrets에 해시·암호화 키가 올바른지 확인. GitHub 저장소에 비밀키나 건강기록 업로드 금지.
- 실제 건강·채팅 정보 대신 **가상 예시 데이터**로 먼저 배포 테스트.

- DB 설정 시 두 브라우저를 열어 서로 다른 기록을 수정하고, 두 번째 저장이 안전하게 거부되는지 테스트.
